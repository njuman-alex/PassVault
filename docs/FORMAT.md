# FORMAT.md — контейнер vault PMV3, иерархия ключей, синк
Версия: 1.0 (утверждена). Изменения — только amendment'ами (v1.1, v1.2…) с записью в DECISIONS.md.

## 1. Цели и ограничения
- Один файл открывается и редактируется на Android и Windows без конвертаций.
- Мастер не прикован к базе: смена мастера = переобёртка одного блоба.
- Синк без сервера и платформенных API: файл в любой синхронизируемой папке
  (Google Drive / OneDrive / Syncthing / флешка); приложения читают и пишут его.
- Миграций нет: формат чистый, старые базы (v1/v2 линейки PassManager) не читаем.
- Метаданные (описания, время правок) — внутри шифра.

## 2. Решения по формату
- Контейнер — JSON-текст, UTF-8, LF, без BOM; бинарные блобы — standard base64 с padding.
- KDF — Argon2id (BouncyCastle, чистая Java). Параметры живут в заголовке.
- Шифр — AES-256-GCM, тег 128 бит, IV 12 байт случайный на каждую операцию.
- id записей — UUID v4 (строка, нижний регистр).
- Магик: "PMV3", formatVersion: 3.

## 3. Иерархия ключей
мастер --Argon2id(salt, params)--> KEK
KEK --AES-GCM wrap--> wrap{salt?, iv, ct(DEK)}   (в заголовке)
DEK (случайные 256 бит, генерится один раз при создании) --AES-GCM--> записи

- Мастер нигде не хранится: только обёртка DEK.
- wraps — массив: сегодня master-обёртка; позже recovery- и device-обёртки
  добавляются элементом массива без смены формата.
- Смена мастера: unwrap старым KEK -> wrap новым KEK -> заменить элемент -> атомарная запись.
  Записи не трогаются.

## 4. Раскладка контейнера
{
  "magic": "PMV3",
  "formatVersion": 3,
  "kdf": { "alg": "argon2id", "memoryKiB": 65536, "iterations": 3, "parallelism": 4, "salt": "<b64>" },
  "wraps": [ { "type": "master", "iv": "<b64>", "ct": "<b64>" } ],
  "records": [ { "id": "<uuid>", "iv": "<b64>", "ct": "<b64>" } ]
}

- ct записи = AES-GCM(DEK, iv, payload, AAD = id), payload:
  { "description": "...", "password": "...",
    "createdAt": <epochMillisUTC>, "updatedAt": <epochMillisUTC>, "deleted": false }
- deleted: true = tombstone (удаление propagate-ится синком).
- Открытым текстом только: magic, formatVersion, kdf, wraps, UUID записей.
  Семантических утечек нет.

## 5. Синк и слияние
- Источник правды — файл в синхронизируемой папке; отдельной локальной базы нет.
- Открыл -> прочитал -> разблокировал -> работаешь.
- Сохранил -> атомарная запись (tmp + rename) -> синк разносит по устройствам.
- Конфликт правок: по каждому id побеждает больший updatedAt;
  tombstone побеждает более старую живую запись. Слияние после разблокировки.
- Конфликт-копии облака: на v1 предупреждаем и предлагаем слить тем же правилом;
  красивый UI — позже.

## 6. Контракт платформенной нейтральности
- UTF-8 везде; base64 standard alphabet + padding, без переносов.
- UUID v4 строкой в нижнем регистре; время только epoch millis UTC.
- Крипта только с явными параметрами: AES/GCM/NoPadding, IV 12, тег 128;
  Argon2id через BC с параметрами из заголовка.
- Никаких дефолтов провайдера, Java-сериализации объектов, Android-only Base64 флагов.
- Порядок полей JSON не значим; парсер терпит неизвестные поля (forward-compat).

## 7. Отложено (не ломает формат)
- recovery-обёртка и device-обёртка (биометрия) — элемент в wraps.
- compaction tombstone-ов, merge-UI конфликт-копий.
- поля notes/url/tags в payload — без bump версии.

## 8. План проверки (до UI)
- Unit-векторы: фиксированный master+params -> детерминированный KEK;
  расшифровка фиксированных блобов на обеих платформах.
- Тесты слияния: конфликт по updatedAt, tombstone vs live, идемпотентность.
- Тест ротации: смена мастера не меняет ct записей; старый мастер не открывает.
